# Стандарты кода

Форма нормы: правило, почему, механизм. Норма без механизма проверяется на ревью. Новая норма появляется, когда подключается библиотека (через ADR) или одно замечание ревью повторилось дважды.

## Комментарии

| Правило | Почему | Механизм |
|---|---|---|
| Обычных комментариев в коде нет, ни `//`, ни `/* */` | Код выражает мысль сам, а комментарий устаревает незаметно | `xtask lint-source` |
| `///` и `//!` только там, где сигнатура не может сказать: инвариант, условие ошибки или паники, ссылка на лемму статьи | Документация для того, чего нет в типах. Пересказ сигнатуры это шум | Ревью |
| `// SAFETY:` обязателен у `unsafe` и это единственное исключение | Clippy `undocumented_unsafe_blocks`, инвариант надо сформулировать | `xtask lint-source`, Clippy |

## Выразительность

| Правило | Почему | Механизм |
|---|---|---|
| Newtype вместо голых чисел: `NodeId`, `ArcId`, типы времени | Вершину нельзя перепутать с дугой | Ревью |
| Enum вместо `bool`-флагов в API | Вызов читается без заглядывания в сигнатуру | Clippy `fn_params_excessive_bools` (pedantic) |
| Невозможные состояния не представимы в типах; инвариант держит конструктор и приватное поле, сеттеров нет | Инвариант остаётся локальным | Ревью |
| Ошибки через `Result`, `thiserror` в библиотеках, `anyhow` в бинарниках | Условия отказа видны в сигнатуре | Clippy |
| `unwrap` только в тестах, `expect("инвариант")` разрешён | Ревьюер видит формулировку инварианта | Clippy `unwrap_used` |
| `unsafe` запрещён; допускается только с замером выигрыша на macro-бенче, изоляцией в модуле, `// SAFETY:` и Miri | Сначала безопасные приёмы | Lint `unsafe_code = deny`, `#[expect(..., reason)]` |
| Каждое исключение из линта содержит `reason` | Исключение должно быть объяснимо | Clippy `allow_attributes_without_reason` |

## Разбиение на файлы и модули

Единица разбиения это модуль и его граница приватности, а не тип и не функция.

| Правило | Почему | Механизм |
|---|---|---|
| Файл отвечает за одну ответственность, названную без «и»: `ttf.rs`, `contraction.rs` | Имя заранее говорит, что внутри | Ревью |
| Имена `utils`, `helpers`, `common`, `misc`, `shared` запрещены | Свалка без ответственности | `xtask lint-source` |
| Вместе живёт то, что вместе меняется и делит инвариант: тип, `impl`, ошибки, итераторы, приватные помощники | Приватность в Rust действует на уровне модуля | Ревью |
| Новый файл появляется, когда есть своя ответственность с отдельными тестами или читателю нужна только часть файла | Разделение не по числу сущностей | Ревью |
| Больше 400 строк это сигнал посмотреть, а не ошибка | Размер не причина, а повод | `xtask lint-source` печатает предупреждение |
| Видимость минимальная: приватно → `pub(super)` → `pub(crate)` → `pub` | Если разделение требует открыть поля, разделили неверно | Lint `unreachable_pub`, ревью |
| Плоский `crates/*`, виртуальный манифест в корне, крейт появляется вместе с первым кодом | Граница крейта отражает реальную зависимость | Ревью |
| В файле публичное и главное сверху, типы раньше функций, родитель раньше потомков | Файл читается как документация API | Ревью |
| `pub use` только на границе крейта | Иначе ломается инкапсуляция | Ревью |

План крейтов: `road-graph` (граф, TTF), `routing` (алгоритмы), `osm-import`, `harness`, `server`, `xtask` (автоматизация).

Вопросы ревью: что новый `pub` выставил наружу? Если удалить модуль, сложность исчезнет или расползётся по вызывающему коду?

## Тесты

| Правило | Почему | Механизм |
|---|---|---|
| Имя теста описывает поведение: `later_departure_never_arrives_earlier` | Имя видно первым в отчёте о падении | `xtask lint-source`: нет префикса `test_`, имя не совпадает с функцией крейта |
| Тест идёт через согласованную публичную границу, приватные функции напрямую не проверяются | Рефакторинг не должен ломать тесты | Ревью |
| Один тест проверяет одно поведение; «and» в имени значит разделить | Понятна причина падения | Ревью |
| Ожидаемое значение из независимого источника: ручной пример, статья, baseline | Пересчёт той же формулой всегда проходит | Ревью, `cargo mutants` |
| Состояние проверяется, вызовы нет; моки только на внешних границах | Тест не зависит от реализации | Ревью |
| Все тесты границы идут через хелпер `check` | Смена сигнатуры правит одно место | Ревью |
| Один интеграционный крейт `tests/integration/` с модулями | Быстрее сборка и общие хелперы | Ревью |
| Золотые графы лежат файлами данных с вручную посчитанными ответами | Новый тест не требует нового кода | Ревью |
| Инварианты проверяет proptest, shrink-пример становится именованным тестом, persistence в git | Находит случаи, о которых не подумали | Ревью |
| `insta` только для текстовых выводов, не для чисел алгоритмов | Иначе неверный результат легко принять как эталон | Ревью |
| Долгие тесты вне быстрого профиля | Быстрая обратная связь | Профиль nextest |
| TDD обязателен для `routing` и `road-graph`; для `osm-import` и `harness` тесты на границах | Здесь ошибка стоит дороже всего | Ревью, `cargo mutants --in-diff` |

Набор свойств для маршрутизации (FIFO, link и merge, сертификат пути, дифференциальный прогон против TD-Dijkstra): `docs/research/project-standards.md`, раздел 4.5.

## Зависимости

- Ядро пишем сами: граф, TTF, CH, CCH, TCH. Инфраструктуру берём из крейтов.
- Каждая зависимость получает одну строку обоснования в `docs/adr/dependencies.md`: она пойдёт в раздел отчёта про выбор инструментов.
- Лицензии и источники проверяет `cargo deny` в CI.
- Копировать код `rust_road_router` нельзя, он только для чтения и как эталон.

## Замеры

- Манифест каждого прогона: git SHA, чистое дерево, `rustc -V`, флаги, CPU, ОС, SHA-256 данных, seed, дата.
- Замеры только на Mac, на питании, без фоновых задач. Счётчики операций публикуются вместе со временем.
- В CI бенчмарки только собираются и проходят один раз как тест.
