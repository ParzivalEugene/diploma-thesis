# Решения по проекту

Статус на 2026-11-02. Подробности и источники: `docs/research/project-standards.md`.

## Постановка

- **Тема (нужно согласовать с руководителем):** «Разработка и экспериментальное исследование методов предобработки графа для поиска маршрута на дорожных сетях с зависящими от времени весами рёбер».
- **Исследовательский вопрос:** как TD-Dijkstra, TD-A\*, TCH и CATCHUp соотносятся по времени запроса, предобработки, памяти и точности на реальной дорожной сети России с суточными профилями.
- **Студент:** Мичков Е.В., группа БПМ-23-РК-1. **Руководитель:** ассистент Вишневский М.Р.
- **Источник требований:** «Требования по НИР (бак. 7-й сем.)» и глава 6 «Рекомендаций Нормоконтроль-ВКР-2019». Версия требований на 2026/27 не найдена, используется версия 2025/26.

## Объём

- **7-й семестр:** отчёт, презентация, база TD-Dijkstra и TD-A\*, CH, CCH, TCH, замеры на OSM.
- **8-й семестр:** свой CATCHUp или развитие существующего, обновления трафика, итоговое сравнение, ВКР.
- **Приоритет:** обязательные разделы отчёта идут раньше TCH. Защита ориентировочно в середине–конце декабря 2026.

## Инструменты и роли

- Код: Rust. Python в проекте не используется, автоматизация лежит в `crates/xtask`.
- Отчёт и слайды: Typst. Слайды на Touying.
- Claude пишет код и текст. Студент ревьюит каждый PR и проходит grilling перед слиянием алгоритмического модуля.
- Использование ИИ в отчёте не указывается: решение студента, согласовано с руководителем со слов студента.

## Данные и замеры

- OSM: Москва и область, затем ЦФО. Импорт `.osm.pbf` на Rust. Профили трафика синтетические, это ограничение указывается в отчёте.
- Замеры только на Mac, условия фиксируются в манифесте. Счётчики операций публикуются вместе со временем.

## Чужой код

- Ядро пишем сами: граф, TTF, CH, CCH, TCH. Инфраструктуру берём из крейтов.
- `rust_road_router` (KIT, BSD-3): чтение и внешний эталон для CATCHUp. Сборку надо проверить отдельным заходом; если не соберётся за один заход, остаётся только чтение.

## Следующие шаги

2. Математическая постановка, концепт системы, код базы.
3. TCH, эксперименты, переработка обзора, презентация, подготовка к защите.
