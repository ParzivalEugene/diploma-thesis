# Стандарты проекта НИР: материал для интервью по решениям

Дата: 2026-11-02. Проект: pure Rust, time-dependent routing на OSM (TD-Dijkstra, TD-A\*, CH, CCH, TCH, позже CATCHUp), отчёт и слайды в Typst, основной автор черновиков Claude, ревьюер студент.

Метки происхождения:

- без метки: первичный источник по ссылке рядом;
- **[М]**: проверено на этой машине 2026-11-02;
- **[В]**: вторичный источник, первичный не найден или недоступен;
- **[С]**: суждение автора заметки, источника нет;
- **[Н]**: не удалось проверить.

## 1. Главное

1. **Текущий шаблон `typst-test/test.typ` даёт межстрочный шаг 21,41 pt [М].** «Полуторный» интервал по метрикам Times New Roman в понимании текстовых процессоров равен 24,15 pt. Разница 12,8 %: 30 страниц превращаются примерно в 34, что двигает границу требования 25–35. Нужно решение (§6.3).
2. **Claude Code официально делит правила на два класса.** CLAUDE.md, промпт и скиллы модель может взвесить и отступить; hooks, deny-правила и CI исполняются всегда (§3.2). Поэтому каждое правило ниже привязано к механизму либо честно названо рекомендацией.
3. **`typst compile` при отсутствии шрифта завершается с кодом 0 и только предупреждает [М],** а флага «warnings как ошибки» в `--help` версии 0.15.1 нет [М]. Сборка на Ubuntu-раннере без TNR пройдёт зелёной с чужим шрифтом, если не проверять stderr и PDF (§6.2).
4. **Самый ценный тест для routing: дифференциальный прогон с независимым baseline и проверка сертификата пути** (§4.5). Покрытие строк эту работу не заменяет.
5. **ГОСТ 7.32-2017 задаёт оформление, но не стиль.** Требования к языку в разделе 6 отсутствуют ([текст, зеркало legalacts](https://legalacts.ru/doc/gost-732-2017-mezhgosudarstvennyi-standart-sistema-standartov-po-informatsii-bibliotechnomu/) **[В]**). 14 pt тоже не из ГОСТа: там «не менее 12 pt». Источник требования 14 pt, 25–35 страниц и 15–20 страниц обзора: постановка задачи студента, методичку МИСИС я не видел **[Н]**.
6. **На машине из нужного есть только `typst` 0.15.1 и `make` [М].** Нет `cargo`, `rustc`, `rustup`, `just`, `vale`, `typstyle`, `poppler`, `gh`; `/usr/bin/java` оказался заглушкой без JRE. Formulae в Homebrew есть для всех, кроме `gh` (не проверял), значит препятствий для установки не видно [М].
7. **Правило памяти «no comments» конфликтует с Rust-практикой:** `// SAFETY:` и rustdoc обязательны для ревью и защиты. Его надо сузить для этого проекта (§2.3).

- `~/.claude/CLAUDE.md` запрещает трейлеры и подписи об авторстве ИИ в коммитах и MR. Это про git.

### 4.3. Линты

[`[workspace.lints]`](https://doc.rust-lang.org/cargo/reference/workspaces.html) наследуется через `[lints] workspace = true`, `priority` у групп [ниже](https://doc.rust-lang.org/cargo/reference/manifest.html), чем у отдельных линтов. Группы линтов ниже сверены со [списком Clippy](https://rust-lang.github.io/rust-clippy/stable/index.html) [М]. Сам блок не собирался: cargo на машине нет [Н].

```toml
[workspace.lints.rust]
unsafe_code = "deny"            # исключение: #[expect(unsafe_code, reason = "...")]
missing_docs = "warn"
unreachable_pub = "warn"
unsafe_op_in_unsafe_fn = "warn"

[workspace.lints.clippy]
pedantic = { level = "warn", priority = -1 }
module_name_repetitions = "allow"
must_use_candidate = "allow"
similar_names = "allow"         # u, v, w в графовом коде
allow_attributes_without_reason = "warn"
unwrap_used = "warn"
dbg_macro = "warn"
todo = "warn"
unimplemented = "warn"
print_stdout = "warn"
iter_over_hash_type = "warn"    # порядок HashMap ломает воспроизводимость
undocumented_unsafe_blocks = "warn"
multiple_unsafe_ops_per_block = "warn"
redundant_clone = "warn"
needless_collect = "warn"

[workspace.lints.rustdoc]
broken_intra_doc_links = "deny"
private_intra_doc_links = "deny"
missing_crate_level_docs = "warn"
unescaped_backticks = "warn"
```

В `clippy.toml`: `allow-unwrap-in-tests = true`.

Почему именно так [С]:

- **`deny` у `unsafe_code`, а не `forbid`:** `forbid` не даёт сделать локальное исключение.
- **Предупреждения становятся ошибками только в CI** (`cargo clippy --all-targets --locked -- -D warnings`), по образцу rust-analyzer. `#![deny(warnings)]` в коде не ставить.
- **pedantic окупается для ИИ-кода:** `cast_possible_truncation` ловит `usize → u32` на идентификаторах вершин, `float_cmp` ловит сравнение времён. Клиппи-бук предупреждает о [щедрых `allow`](https://doc.rust-lang.org/clippy/lints.html), поэтому каждое исключение требует `reason`.
- **Не включать `indexing_slicing`, `arithmetic_side_effects`, `as_conversions`, `float_arithmetic`:** графовый код состоит из индексации и арифметики, шум задавит сигнал.
- **`expect("причина")` разрешён**, `unwrap` нет: ревьюер видит формулировку инварианта.

Rustdoc-уровни из [справочника](https://doc.rust-lang.org/rustdoc/lints.html): `missing_doc_code_examples` только на nightly, не использовать.

### 4.4. Архитектура, ошибки, unsafe

- **Workspace.** [Виртуальный манифест](https://doc.rust-lang.org/cargo/reference/workspaces.html), `resolver = "3"`. Предложение [С]: `crates/routing` (библиотека: графы, TTF, алгоритмы), `crates/osm-import`, `crates/harness` (бинарник экспериментов). Алгоритмы как модули библиотеки, а не отдельные крейты: так сделано в `engine/src/algo` у KIT, и граница «один трейт запроса» важнее границы крейта.
- **Типы.** [C-NEWTYPE, C-CUSTOM-TYPE](https://rust-lang.github.io/api-guidelines/checklist.html): `NodeId(u32)`, `ArcId(u32)`, `Timestamp`, `Duration`. Из чеклиста брать Naming, Type safety, Debuggability, C-FAILURE; `C-SERDE`, `C-METADATA`, `C-RELNOTES` для непубликуемого кода лишние [С].
- **Представление времени** (целые мс или `f64`) определяет корректность FIFO и сравнения: ADR до начала кода. В `rust_road_router` CATCHUp живёт в модуле `floating_time_dependent`, статья хранит функции как периодические кусочно-линейные с точками излома ([Strasser et al.](https://ar5iv.labs.arxiv.org/html/1910.12726)).
- **Ошибки.** По [dtolnay](https://github.com/dtolnay/anyhow): `thiserror` в библиотеке, `anyhow` в бинарниках. [C-GOOD-ERR](https://rust-lang.github.io/api-guidelines/checklist.html). В горячем пути `Option` для «недостижимо», паники только на нарушенный инвариант, `debug_assert!` на дорогие проверки [С].
- **Unsafe.** По умолчанию нет. Условия допуска [С]: профиль показывает выигрыш на macro-бенче; безопасные приёмы исчерпаны ([perf book](https://nnethercote.github.io/perf-book/bounds-checks.html) называет `get_unchecked` крайней мерой и напоминает, что проверки границ обходятся дешевле, чем ожидают); код изолирован модулем ([Nomicon](https://doc.rust-lang.org/nomicon/working-with-unsafe.html): граница надёжна только через приватность); `// SAFETY:` с инвариантом ([std-dev-guide](https://std-dev-guide.rust-lang.org/policy/safety-comments.html)); Miri на этих тестах.
- **Сборка.** [perf book](https://nnethercote.github.io/perf-book/build-configuration.html): `codegen-units = 1`, `lto = "fat"`, `panic = "abort"`, `target-cpu=native`, debug-символы для профилирования. Отдельный `[profile.bench-final]`, чтобы обычная сборка не стала медленной [С]. Тесты на больших графах требуют `opt-level` в dev, как у ruff и KIT, а `overflow-checks` оставить включёнными [С].

### 4.5. Тесты для routing

Основания: FIFO и его роль ([Bast et al., §2.7.4](https://ar5iv.labs.arxiv.org/html/1504.05140): Dijkstra работает при запрете обгона; [Strasser et al.](https://ar5iv.labs.arxiv.org/html/1910.12726): σ ≤ τ ⇒ σ + f(σ) ≤ τ + f(τ), без FIFO и без ожидания задача NP-трудна, ссылка на Orda и Rom). Первоисточник про Dreyfus и Kaufman–Smith я не прочитал [Н]. Набор свойств ниже мой [С], опирается на эти определения.

| Уровень | Свойство | Что ловит |
|---|---|---|
| TTF | FIFO генератора и после каждого link и merge | Основную ошибку функций времени |
| TTF | Периодичность: f(τ + Π) = f(τ) | Границы периода |
| TTF | `link(f,g)(τ) = f(τ) + g(τ + f(τ))` по точкам, `merge(f,g)(τ) = min` | Операции TCH и CATCHUp |
| TTF | Упрощение точек излома в пределах допуска; ε задаётся в ADR | Накопление погрешности |
| Baseline | Золотой набор: 5–10 графов, ответы посчитаны вручную и записаны студентом | Общий баг baseline и всех остальных |
| Baseline | Константные TTF: TD-Dijkstra = статический Dijkstra | Логику времени |
| Дифференциальный | TD-A\*, CH, CCH, TCH, CATCHUp дают то же время прибытия, что TD-Dijkstra, на случайных (s, t, τ) | Ошибки ускорения |
| Сертификат | Путь в ответе существует; пересчёт по дугам даёт ответное время | Верный ответ при неверном пути и наоборот |
| Монотонность | EA(s,t,σ) ≤ EA(s,t,τ) при σ ≤ τ | Нарушение FIFO на уровне запроса |
| A\* | π(v) ≤ нижняя граница до t, потенциал допустим | Неоптимальные пути |
| CCH | Кастомизация новой метрикой = полная пересборка | Состояние, оставшееся от старой метрики |
| Границы | s = t, недостижимая t, τ у границы периода, петли, параллельные дуги | Граничные случаи |

Правила прогона [С]:

- **Два масштаба.** Быстрый: proptest на графах до ~200 вершин, в каждом `just check`. Полный: 100 000 случайных запросов на реальном экстракте (такой объём у Strasser et al.), вне каждого коммита.
- **Независимость оракула.** Baseline не использует код ускорений, минимален, читается студентом целиком; TTF-оценка покрыта отдельными свойствами и ручными примерами. Иначе получается тавтология из скилла `tdd`.
- **Внешний контроль.** Разовая сверка с `rust_road_router` на маленьком графе, если его удастся собрать: в статье использован nightly 1.49, в репозитории пина нет [С].
- **Регрессии.** Файл persistence от proptest в git; shrink-пример превращается в именованный тест.
- **Качество тестов.** `cargo mutants --in-diff` на изменённых алгоритмах перед слиянием.

### 4.6. Воспроизводимость бенчмарков

Что фиксировать: образец [Strasser et al.](https://ar5iv.labs.arxiv.org/html/1910.12726) указывает CPU, RAM, ядра, отключённый hyper-threading, ОС, версии `rustc`, флаги сборки; запросы общие для всех конкурентов (100 000 случайных троек s, t, τ); Dijkstra rank по степеням двойки ([метод Sanders–Schultes в обзоре Bast et al., §3.1.1](https://ar5iv.labs.arxiv.org/html/1504.05140)); 5 повторов препроцессинга со средним; машинно-независимые метрики (извлечения из очереди, вычисления функций); код открыт.

Риски:

- [Mytkowicz et al., ASPLOS 2009](https://sape.inf.usi.ch/publications/asplos09): размер окружения UNIX и порядок линковки смещают результат настолько, что меняется вывод; ни одна из 133 статей обзора этого адекватно не учитывала; лечение: рандомизация настройки и причинный анализ. Для отчёта достаточно прогонять разные окружения и честно описывать ограничения [С].
- [Criterion FAQ](https://bheisler.github.io/criterion.rs/book/faq.html): шум виртуализации делает замеры в CI ненадёжными.
- [Perf book](https://nnethercote.github.io/perf-book/benchmarking.html): wall-time шумный, небольшие изменения раскладки памяти дают скачки; при этом «Mediocre benchmarking is far better than no benchmarking».

Предложение [С]:

| Артефакт | Решение |
|---|---|
| Микро (eval, link, merge) | `criterion` в `benches/`; в CI только сборка и один прогон как тест |
| Макро (запросы и препроцессинг) | Свой `harness`: seed, файл запросов, вывод CSV |
| Манифест каждого прогона | git SHA, грязное дерево как ошибка, `rustc -V`, флаги, CPU, ОС, SHA-256 данных, seed, дата |
| Счётчики | Feature `metrics`: pops, relaxations, TTF-вычисления, размер индекса; результат не зависит от машины |
| Данные | Экстракт [Geofabrik](https://download.geofabrik.de/technical.html) с датой в имени (старые файлы со временем удаляются, поэтому хранить SHA-256 и копию вне git); [ODbL требует атрибуции](https://www.openstreetmap.org/copyright) |
| TD-профили | В OSM их нет. Генератор с seed и проверкой FIFO; описание в отчёте как ограничение [С] |
| Машина | Одна, на питании, без фоновых задач. Для macOS нет управления частотой как в Linux [Н]: решить, где идут финальные замеры |

Источник нормы научного стиля (например, Мильчин, Чельцова, «Справочник издателя и автора») я не открывал [Н]: если важен авторитет, сверить вручную.

### 5.6. ГОСТ 7.32-2017: что проверяемо

По [зеркалу текста](https://legalacts.ru/doc/gost-732-2017-mezhgosudarstvennyi-standart-sistema-standartov-po-informatsii-bibliotechnomu/) **[В]**: A4, полтора интервала, чёрный, не менее 12 pt, рекомендован TNR, поля 30/15/20/20, абзац 1,25 см, полужирный только для заголовков (6.1.1); заголовки структурных элементов прописными по центру, разделы с новой страницы, без переносов (6.2); нумерация с титула, номер внизу по центру, на титуле не ставится (6.3); перечисления через тире (6.4.6); «Рисунок 1 – Название», ссылка обязательна (6.5); «Таблица N – Название» слева сверху, ссылка обязательна (6.6); формулы по центру, номер справа (6.8); ссылки `[N]`, источники в порядке упоминания (6.9, 6.16); единицы по ГОСТ 8.417; сокращения по ГОСТ 7.11, 7.12. Список сокращений обязателен от трёх условных обозначений (5.6.3).

Обязательность структурных элементов на зеркале потеряна с полужирным: сверить с оригиналом [Н].

### 5.7. Цитирование: отдельный гейт

Выдуманные источники самый опасный дефект ИИ-черновика в НИР [С], W выделяет их отдельно. Правила: каждая запись содержит DOI, ISBN или URL; студент открывает источник и находит цитируемое место; поле `note` с номером страницы; сценарий проверяет, что DOI резолвится (сеть, только идентификаторы, текст не уходит). Автоматика ловит несуществующее, но не искажение смысла: это остаётся ручной работой.

### 6.2. Что показала проверка [М]

Работа шла на копии `typst-test` в scratchpad, исходники не менялись.

- **Шрифт.** В PDF: `TimesNewRomanPSMT`, `TimesNewRomanPS-BoldMT` и `STIXTwoMath-Regular`. Математика не в TNR по явному `show math.equation`; ГОСТ это не запрещает, но позицию кафедры я не знаю [Н].
- **Кегль.** В потоках страниц встречаются 14, 9,8 и 7,7 pt. Последние, видимо, индексы. Проверять кегль надо по телу текста, а не по всем символам.
- **Нет шрифта.** `--ignore-system-fonts`: `warning: unknown font family`, **код выхода 0**. Флага для ошибок на предупреждениях нет. `fallback: false` оставляет «тофу» [без предупреждения](https://typst.app/docs/reference/text/text/). В CI: падать на непустом `warning:` в stderr и проверять PDF.
- **TNR локально есть**, `/System/Library/Fonts/Supplemental`. На Ubuntu-раннере его нет [С]; [Liberation](https://github.com/liberationfonts/liberation-fonts) совместим по ширине по заявлению проекта, но для проверки верстки это другой шрифт.
- **`typst query` объявлен устаревшим,** подсказка ведёт к `typst eval --in`. `query(<label>)`, `location().page()` и `query(cite)` работают; `counter(page).final()` через `eval` возвращает объект context, а не число. Общее число страниц брать из `pdfinfo` или метки в конце документа.
- **Библиография.** Встроен только [`gost-r-705-2008-numeric`](https://typst.app/docs/reference/model/bibliography/). ГОСТ Р 7.0.100-2018 надо сверить с кафедрой: возможно, потребуется свой CSL [Н]. В `test.typ` стоит `full: true`: в список попадут и незацитированные. В отчёте поставить `false`, тогда автоматически «список = цитируемое».
- **Воспроизводимость.** При фиксированном `SOURCE_DATE_EPOCH` два PDF совпали по SHA-1. Есть также `--creation-timestamp`.

### 6.3. Межстрочный интервал: нужно решение

Замеры по базовым линиям одного абзаца [М]:

| Настройка | Шаг | Комментарий |
|---|---|---|
| `test.typ`: ascender/descender, `leading: 0.62em` | **21,41 pt** | Почти буквально 1,5 × 14 = 21 |
| Там же, `leading: 0.7em` | 22,53 pt | |
| `top-edge: 1em`, `bottom-edge: 0em`, `leading: 0.725em` | **24,15 pt** | 1,5 одинарного по метрикам шрифта |

Таблица `hhea` локального TNR: ascender 1825, descender −443, lineGap 87 при 2048 единицах, одинарный интервал 1,1499 em; ×1,5×14 = 24,15 pt [М]. Что Word считает именно так, я вывел из метрик и известной практики, спецификацию не читал [Н]. ГОСТ говорит только «полтора интервала» и величину в пунктах не задаёт. Если проверяющий откроет PDF рядом с документом Word, совпадёт 24,15 pt [С].

### 6.4. Правила Vale

[Substitution](https://docs.vale.sh/checks/substitution) поддерживает регулярные ключи и `affix` (v3.25+) для форм слова по hunspell-файлу. Пример:

```yaml
# .vale/styles/Nir/Kantselyarit.yml
extends: substitution
message: "'%s' лучше заменить: %s"
level: suggestion
ignorecase: true
swap:
  'в данн\w+': "в этом/этой, либо имя объекта"
  'в рамках': "в"
  'посредством': "с помощью или творительный падеж"
  'имеет место': "глагол: снижается, растёт"
  'с целью': "чтобы"
```

Уровни [С]: `error` заглушки и чат-артефакты; `warning` §5.3, вводные и оценки; `suggestion` канцелярит, где термин может дать ложную тревогу. Исключения: цитаты, названия источников.

Риск **[Н]**: поведение `\b` на кириллице не проверено, Vale не установлен, в исходнике [substitution.go](https://github.com/errata-ai/vale/blob/v3/internal/check/substitution.go) видно использование `regexp2` и обычного `regexp`. Первый шаг после установки: тест на фразах из §5.2, в том числе на ложные срабатывания внутри слова. План Б: `rg -f` с тем же списком (`ripgrep` даёт `\b` по Unicode по умолчанию, [С], не проверено на этой машине) и маленький скрипт вывода.

## 7. Как связать

### 7.1. Уровни

| Уровень | Плюсы | Минусы | Что на нём |
|---|---|---|---|
| [`just`](https://just.systems/man/en/) | Один источник команд; нет `.PHONY`, список рецептов, аргументы; [CC0](https://github.com/casey/just) | Лишняя зависимость по сравнению с `make`, который есть [М] | **Всё.** Остальные уровни только вызывают рецепты |
| Claude Code hooks | Реакция сразу, обратная связь идёт модели | Работают только в Claude Code; нужно обслуживать | Формат после правки; `check-fast` на Stop |
| [pre-commit](https://pre-commit.com/) (фреймворк) | Экосистема, `--all-files` | Python-инструмент, вторая конфигурация, те же команды | **Не брать.** При желании голый `.git/hooks/pre-push` с `just check-fast` |
| GitHub Actions | Независимо от агента и машины; чистая среда; виден статус | Настройка, скорость; шрифт TNR | Полный `just check`, отчёт, недельные задачи |

Для одного человека на два семестра окупаются `just`, два hook и один workflow; фреймворк хуков нет [С]. GitHub Actions: в [публичных репозиториях бесплатно, для приватных на Free включено $12 в месяц](https://docs.github.com/en/billing/concepts/product-billing/github-actions), что примерно 2000 минут Linux; при тяжёлых тестах стоит следить за минутами.

### 7.2. Рецепты

`fmt`; `check-fast` (формат, clippy `-D warnings`, nextest быстрого профиля); `check` (плюс doctests, `cargo doc -D warnings`, typos, сборка отчёта); `report` (typst с проверкой `warning:` в stderr); `report-check` (плюс `tools/report_check.py` и Vale); `mutants` (`--in-diff` от `main`); `bench-micro`; `exp` (harness → `results/` и манифест). Файл не создавался, `just` не установлен.

### 7.3. Claude Code hooks (не больше двух)

- `PostToolUse` на `Write|Edit`: `rustfmt` для `.rs`, `typstyle -i` для `.typ`. Паттерн из [best practices](https://code.claude.com/docs/en/best-practices). Требует `typstyle` в PATH.
- `Stop`: если в дереве есть изменения `.rs` или `.typ`, запустить `just check-fast`, вывод в stderr, код 2 при падении. Нужен быстрый профиль: сборка тестов с `opt-level` может идти десятки секунд [С]. Без фильтра по изменениям hook будет гонять проверки даже после разговорного ответа.

Deny-правила в `.claude/settings.json`: `Edit(results/**)`, `Write(results/**)`. Глобальные запреты на push в `main` уже действуют.

Claude Code hooks не заменяют CI: правки студента и правки с других машин они не видят.

### 7.4. GitHub Actions

| Job | Раннер | Шаги |
|---|---|---|
| `rust` | `ubuntu-latest` | Toolchain из `rust-toolchain.toml`, кэш, `just check` |
| `report` | `macos-latest` | setup-typst с пином, `just report-check`. Причина выбора: TNR входит в macOS [М локально], на раннере проверить первым запуском [Н]. Минуты macOS дороже на приватном репо |
| `weekly` | `ubuntu-latest`, по расписанию | `cargo deny check advisories sources`, полный дифференциальный на малом экстракте, `llvm-cov` как артефакт |

Бенчмарки в CI не мерить: только сборка и один проход как тест, по [Criterion FAQ](https://bheisler.github.io/criterion.rs/book/faq.html). Действия в ответственных проектах прикрепляют к SHA (typst/typst так делает с `dtolnay/rust-toolchain` [М]); для учебного проекта достаточно мажорных тегов [С].

## 9. Что решить

Формат: вопрос, варианты, рекомендация; сначала то, от чего зависит остальное.

- **Р-1. Какое значение «1,5 интервала» принимаем?** 21,41 pt (как сейчас), 21 или 24,15 pt. Рекомендация: 24,15 pt, настройка из §6.3; уточнить у кафедры, есть ли образец. Влияет на все счётчики страниц.
- **Р-2. Источник правды по требованиям МИСИС.** Постановка студента или методичка кафедры. Рекомендация: добыть документ кафедры до шаблона; положить в `docs/` с датой. Уточнить: что входит в 25–35 страниц, ГОСТ Р 7.0.5 или 7.0.100, допустим ли шрифт формул.
- **Р-3. Раскладка репозитория.** Один репозиторий на код, отчёт и слайды или разделённые. Рекомендация: один, §3.4: отчёт читает `results/` напрямую.
- **Р-4. Публичный или приватный GitHub-репозиторий.** Рекомендация: приватный до защиты, потом открыть код. Цена: лимит минут, дорогие macOS-минуты. Если кафедра не против открытости раньше, публичный снимает лимиты; TNR в репозиторий не класть ни в каком варианте.
- **Р-5. Где живут нормы и какой они формы.** Рекомендация: короткий `CLAUDE.md` + `.claude/rules/` по путям + `CODING_STANDARDS.md` и `WRITING_STANDARDS.md`, без AGENTS.md. Вместо корпуса как в рабочий проект упрощённая форма: сила, правило, почему, механизм; норма без механизма помечается «рекомендация».
- **Р-6. Как обеспечить, что студент может объяснить всё.** Варианты: только ревью PR; ревью + собственное объяснение; устный разбор (`grilling` или `teach`). Рекомендация: PR на каждую фичу, цель до ~400 строк ([Google: 100 обычно разумно, 1000 обычно слишком много](https://google.github.io/eng-practices/review/developer/small-cls.html), 400 мой компромисс); перед слиянием алгоритмического модуля сессия `grilling`; итог в `docs/explain/<модуль>.md` написан студентом своими словами, без ИИ-черновика. Этот файл и станет подготовкой к защите.
- **Р-7. Правило про комментарии.** Рекомендация: нарративных нет; `///` на публичном API и `// SAFETY:` обязательны; комментарий допускается про факт, невыводимый из кода (ссылка на лемму статьи). Обновить память `code-style` для этого проекта.
- **Р-8. Язык кода.** Рекомендация: идентификаторы, rustdoc, коммиты на английском; отчёт на русском; `GLOSSARY.md` связывает термины. Сообщения об ошибках на английском.
- **Р-9. Строгость Clippy.** Варианты: как rust-analyzer (без pedantic), как ruff (pedantic с исключениями). Рекомендация: как ruff, блок §4.3, `-D warnings` только в CI. Пересмотреть через месяц по числу `#[expect]`.
- **Р-10. Unsafe.** Рекомендация: `deny`, вход только через условия §4.4. Miri подключается вместе с первым `unsafe`.
- **Р-11. Представление времени.** Целые мс или `f64`. Рекомендация: это первый ADR; студент решает после чтения CATCHUp и TCH. Я склоняюсь к целым для baseline и TD-Dijkstra, но это не проверено на аппроксимации TCH [С].
- **Р-12. Строгость тестов.** Рекомендация: `tdd` обязателен для `routing`, для `osm-import` и `harness` тесты на границах; seams: трейт запроса, операции TTF, импорт файла. `cargo mutants --in-diff` вручную на алгоритмах, порог покрытия не вводить.
- **Р-13. Где идут финальные замеры.** Mac или Linux-машина. Рекомендация: выбрать одну до первых замеров и не менять; при наличии Linux брать её (HT и частота управляются). Счётчики операций публиковать в любом случае.
- **Р-14. Данные и TD-профиль.** Рекомендация: один малый экстракт для тестов и один крупный для отчёта, SHA-256 в git, файлы вне git; генератор профиля с seed. Содержание генератора отдельный ADR.
- **Р-15. Связка проверок.** Рекомендация: `just` + 2 hook + 1 workflow; без pre-commit-фреймворка. Если лишняя зависимость нежелательна, `make` работает без установки, но теряет список рецептов и аргументы.
- **Р-16. Каталог текста и внешние сервисы.** Рекомендация: §5 в `WRITING_STANDARDS.md`, Vale с тремя уровнями, первым смоук-тест на кириллице; если не заработает, план Б из §6.4. По умолчанию локально (Vale + Hunspell), LanguageTool локально перед сдачей глав, Спеллер и Главред разово вручную, в CI только локальное.
- **Р-17. Формат отчёта в CI.** Варианты: macOS-раннер с настоящим TNR; Ubuntu с установкой шрифта (условия EULA не изучал [Н]); локальная проверка, а в CI только сборка. Рекомендация: начать с локальной `just report-check` + CI-компиляция на macOS с проверкой stderr; решение пересмотреть по стоимости минут.
- **Р-18. Трекер задач.** GitHub Issues или локальные markdown-файлы (оба поддерживаются `setup-matt-pocock-skills`). Рекомендация: GitHub Issues после установки `gh`; скилл предварительно обновить (§2.1).
- **Р-19. Использование `rust_road_router`.** Варианты: внешний оракул, чтение, копирование. Рекомендация: чтение и оракул; весь код писать заново и ссылаться на статью. Копирование уменьшает объём, который студент реально защищает [С], а BSD-3 требует сохранения уведомлений.
